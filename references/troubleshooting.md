# Safe recovery

| Result / symptom | Host action |
|---|---|
| `ASR_REQUIRED`, no captions | Ask for SRT/VTT/TXT or, where supported, explicit prepared local ASR. Do not use title/description as a spoken transcript. |
| `CAPABILITY_MISSING` | Explain the missing runtime/model. Obtain approval before installation or choose another source/transcript. No model download occurs automatically. With `Cause: asr-runtime-failed` the configured whisper executable or model failed to run (a missing DLL, an incompatible build, a file that is not a whisper.cpp model); the source was not rejected. `Cause: windows-script-wrapper`: configure the `.exe`, not a `.cmd`/`.bat` wrapper. |
| Any YouTube acquisition failure | Run `scripts/canary.mjs` first: `BLOCKED` means a policy/approval decision, `BROKEN` means update bgutils-js/jsdom/yt-dlp or fix the adapter, `NO_CAPTIONS`/`UNAVAILABLE` means the video, not the tooling. |
| `NETWORK_UNAVAILABLE` (`Cause: network-unavailable`) | This process could not resolve or reach the source (DNS or connection failure). The usual cause is a host agent running commands in a sandbox without network (Codex `workspace-write` blocks network by default). Ask the user to allow network for the skill's commands (or run the host with network access) and retry; it is not a refusal by YouTube, so do not switch to capture import or ASR for it. Otherwise check the URL and connectivity. |
| `CAPTIONS_ANDROID_CLIENT` warning | No proof-of-origin token could be used here (not macOS, a host sandbox, or the token was refused), so the track was read from YouTube's Android-app caption list: same language and kind as the web choice when listed. Nothing to fix; the transcript is the same platform track. |
| `SOURCE_ACCESS_DENIED` (`Cause: transcript-refused` / `transcript-refused-no-token`) | Both the web track and the Android-app caption list failed. YouTube may have extended its token gate to the Android client: run the canary, update the skill, or offer a transcript / host-browser capture. No cookies, proxies or further clients are tried. |
| `SOURCE_ACCESS_DENIED` (`Cause: bot-check`) | The watch page itself demands sign-in; tokens do not help. Offer a transcript or another source. |
| `ASR_REQUIRED` on YouTube | No captions. With approval, set `asr: local` and pass `--yt-dlp-executable` (current release) plus the whisper executable/model; note YouTube's download terms and that audio stays in the private job. |
| `SOURCE_ACCESS_DENIED` (`Cause: age-restricted` / `login-required`) | Signed-in viewing is required and not supported; ask for a transcript or another source. |
| `SOURCE_UNAVAILABLE` | The video is removed, private, region-blocked or the ID is wrong; confirm the link with the user. |
| `TRANSCRIPT_UNAVAILABLE` (`Cause: no-transcript`) | The video exposes no transcript (captions disabled or none uploaded). Ask for SRT/VTT/TXT; for local media, approved local ASR or local OCR may apply. |
| `AUTOMATIC_CAPTIONS` warning | The track is auto-generated: no punctuation and mangled technical terms are likely; prefer a manual track via `policy.transcriptLanguages` when one exists, and read quotations with care. |
| `ASR_MODEL_COMPACT` warning | The model file is under 1 GiB and its GGML header was not recognized as large-v3-turbo. A small file can also be a quantized larger model, so size alone does not establish quality. Check numbers, conditions and negations against the source; see the support matrix. |
| `ASR_LANGUAGE_RECHECK` warning | Optional ko/en recheck used the same Whisper model to revisit short Latin-only segments. Inspect original/revised text in private `raw/extraction.json` → `localAsrLanguageRecheck`; retained timing is still approximate. A limited recheck hit its count/time cap or a tool failure; it does not mean every language switch was checked. Names, missing speech and mixed segments can remain wrong. Do not merge the separate `asr-review` suggestions automatically. |
| `ASR_GPU_FALLBACK` warning | The GPU runtime was unavailable or failed and local ASR used the CPU. Check the configured executable and compatible native libraries. On WSL, an inaccessible `/dev/dxg` may indicate unavailable GPU support or a host sandbox/device-access policy; do not infer a driver mismatch from a CUDA error alone or silently disable isolation. See [WSL setup](wsl.md). Long CPU transcription may require a larger `asrTimeoutMs`, chosen with the user. |
| `ASR_SUSPECT_SEGMENTS` warning | The listed segments match phrases Whisper invents over music or silence (subtitle credits such as “Korean subtitles by …” — an English rendering of a Korean example — “thanks for watching”, subscribe requests), or are only a sign-off such as “Thank you.” stretched over at least five seconds or over mostly silent audio. Check the source at those times; do not cite them as speech unless confirmed. Nothing was removed. |
| `ASR_GAPS_RETRANSCRIBED` warning | The first pass left stretches with sound untranscribed (often speech in a second language), so each was transcribed again on its own with its own language detection, as WhisperX and faster-whisper's multilingual mode transcribe chunks. The listed segments came from that pass; check them against the audio like any ASR text. Retried stretches are in private `raw/extraction.json` → `localAsrGapFill`. |
| `MEDIA_DURATION_CORRECTED` warning | The file's header length and the length its audio actually decodes to differ (a download or copy cut short, or raw AAC whose header only estimates). The decoded length is used; a supplied transcript that runs past it is then refused as `transcript-duration-overrun`. |
| `TRANSCRIPT_END_CLAMPED` warning | Cues ended at most 50 ms after the media's end (codec delay and padding), as happens when a file is re-encoded after its subtitles were made; their end was set to the media's end. Original times are in private `raw/extraction.json` → `transcriptEndClamped`. |
| `TRANSCRIPT_REORDERED` warning | The supplied or published transcript listed cues out of time order; they were sorted by start time as players do. Overlapping cues are kept. |
| `PLAYBACK_MEDIA_TRANSCODED` warning | Browsers cannot decode the source's audio codec, so the HTML player (and an approved media copy) uses an AAC copy. Evidence and citations come from the original file. |
| `ASR_UNTRANSCRIBED_AUDIO` warning | Stretches of at least five seconds with at least three seconds of sound (above about −45 dBFS) have no transcript. They can be music, applause or other non-speech, or speech Whisper skipped, most often after a language change. Listen at the listed times; for suspected speech run `asr-review` on that range. The ranges are also in private `raw/extraction.json` → `localAsrCoverage`. Nothing was added to the evidence. |
| `MULTIPLE_AUDIO_TRACKS` warning | The file has several audio tracks and local ASR transcribed only the one FFmpeg selects by default. If the user means another track (another language, commentary), ask for its transcript or a file with only that track. |
| `PODCAST_FEED_UNAVAILABLE` / `PODCAST_TRANSCRIPT_UNUSABLE` warning | The show's feed, or the transcript it lists, could not be fetched or parsed (for example a feed URL that no longer exists after a host change). The episode audio was used instead, so the evidence comes from local ASR when approved; otherwise `ASR_REQUIRED` follows. |
| `TIMING_UNAVAILABLE` after local ASR | A cue beyond the known media duration keeps its text but has no usable timestamp. Inspect original intervals in private `raw/extraction.json` → `localAsrTiming` and compare the audio. Do not clip the time to the end of the media or treat the text as confirmed speech. Other causes, such as untimed supplied text, can produce this warning too. |
| `INVALID_CONTRACT` after local ASR | Read the fixed `Cause:` for parsing, cue-count, empty-text or timing failures. If saved, the error names a private `raw/asr-failures/<attempt>/` directory with bounded `transcript.srt` and a request-bound `receipt.json`. Earlier failures remain separate. This output is not validated evidence, must not be published or promoted to a cache hit, and may contain invented text or invalid times. Supplied SRT/VTT remains strictly validated. |
| Linux PDF: Chromium aborts with `Failed to move to new namespace … Operation not permitted` | The browser sandbox cannot create its namespaces. In Docker, the default seccomp profile blocks them: run the container with `--security-opt seccomp=unconfined` (or a profile that allows user namespaces). On Ubuntu 23.10+, unprivileged user namespaces are restricted by AppArmor for unconfined programs: use a browser package that ships an AppArmor profile. Never disable the sandbox to make PDF work. |
| Linux: whisper.cpp build fails with `inlining failed … target specific option mismatch` | GCC on arm64 with native CPU detection; configure with `-DGGML_NATIVE=OFF -DGGML_CPU_ARM_ARCH=armv8.2-a+dotprod+fp16`. CPU-only turbo runs near real time on 4 threads: raise `asrTimeoutMs` (default 1 h) for long videos or use a smaller model with the `ASR_MODEL_COMPACT` caveats. |
| `VISUAL_OCR_UNVERIFIED` warning | Frame text is machine-read from sampled scenes; open each frame before citing, and expect unsampled scenes. |
| `SOURCE_UNSUPPORTED` | Explain the unsupported source/platform or ASR path. A user transcript may be sufficient. `Cause: no-decodable-audio`: the file has an audio stream but nothing could be decoded (for example a truncated or header-only file). |
| `UNSAFE_PATH` | `Cause: path-not-found`: check the path for typos and quoting; `Cause: path-not-file`: a folder or shortcut was given instead of a file. |
| `EBUSY` | Another program holds the file without sharing it (on Windows, some editors and recorders do). Ask the user to close it and retry. |
| `INVALID_CONTRACT` (`Cause: transcript-format-unsupported` / `transcript-encoding-unsupported`) | Convert the transcript to SRT, VTT or TXT (for example SAMI `.smi` to SRT) and save it as UTF-8. An encoding is refused only when it is neither UTF-8 nor BOM-marked UTF-16 and cannot be detected with confidence, usually because the file has too little non-ASCII text. |
| `TRANSCRIPT_ENCODING_DETECTED` warning | The supplied transcript was not UTF-8 and was read in the code page named in the message (for example `euc-kr` for CP949). Compare a few lines with the source; if they look wrong, ask for a UTF-8 copy. |
| `UNSAFE_URL` | Do not disable network checks. Credentials, private addresses and unsafe redirects are refused. Ask for a public source or authorized local file. |
| `RESOURCE_LIMIT` / `TIMEOUT` | Explain the configured budget. Only increase it with a reasoned user decision; use a new acquisition work directory. Never silently truncate evidence. |
| `UNREVIEWED_EVIDENCE` | Finish reviewing chunks or obtain exact partial-scope approval. Do not forge ledger entries or consent. |
| `EVIDENCE_MISMATCH` | Use the correct immutable snapshot. Changed source/transcript requires a new work directory; changed report/evidence requires a new output revision. |
| `UNCONFIRMED_FRAME` | Inspect the actual image or remove unsupported visual claims. Do not mark inspection just to pass. |
| `PDF_RUNTIME_MISSING` | Select an installed Chrome/Chromium executable or ask permission to install one. Retain successful HTML/MD and report the overall job incomplete. |
| `PDF_CLEANUP_FAILED` or a PDF cleanup warning | Browser closure or private temporary-data removal could not be confirmed. Keep the requested PDF stage incomplete; preserve any primary rendering error. If a temporary directory basename is reported, confirm the browser has stopped and inspect that directory before manual cleanup. No absolute private path or native diagnostic is exposed. |
| Codex PDF fails before page creation | A tested workspace-write run aborted Chrome at launch (SIGABRT, cleanup EPERM). Diagnose the host's browser-launch permissions; do not assume a font/report defect or disable either sandbox. Keep PDF incomplete until an authorized runtime succeeds. |
| `EXPORT_FAILED` … sandbox probe was refused | An explicit sandbox permission refusal suggests that a host sandbox may be preventing Chrome's own sandbox from starting; it does not prove the cause. Try an approved export outside the host sandbox; HTML and Markdown are unaffected. Unclassified probe exits/signals are not diagnosed as nesting. Never disable Chrome's sandbox. |
| `EXPORT_FAILED` / PDF font issue | Check selected browser, sandbox support and local fonts. Retry PDF against the same report with `--font-dir`; visually inspect it. Do not disable the browser sandbox as a silent fallback. |
| `BUSY` | Another writer holds `.write.lock` and refreshed it within the last 30 seconds. Wait for it to finish; never remove a live lock. A writer refreshes its lock every 5 seconds (as proper-lockfile does), so a lock left by a killed writer goes stale after 30 seconds and the next run takes it over. |
| `STALE_LOCK_RECOVERED` warning | A lock that had not been refreshed for 30 seconds was replaced, usually after a cancelled or killed run. Nothing else is needed; earlier partial files in that directory follow the usual immutability rules. |
| `LOCK_COMPROMISED` | Another process took over the lock while this one was still writing (it saw no refresh for 30 seconds, for example after the system stalled). Treat the output as unreliable and rerun in a new job or revision. |
| `OUTPUT_EXISTS` | Choose an empty output revision; do not overwrite unrelated user files. |
| `PREVIOUS_INSTALL_RETAINED`, `PREVIOUS_INSTALL_CHANGED`, or installer recovery paths | Previous/failed copies are intentionally retained rather than recursively deleted. Verify the active install, stop related processes, and inspect the exact reported path before manual recovery or cleanup. A changed directory is not permission to delete it. |
| Player fails or `file://` source is unavailable | Keep reading the transcript; use original-source links or the loopback server for authorized local playback. Do not promise offline embedding. |

A nonzero script exit does not mean all earlier outputs are lost. Inspect the result envelope and public manifest, retain verified successful files, and retry only the missing stage where possible. Do not mark a failed PDF as successful because HTML can be manually printed later.
