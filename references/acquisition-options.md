## YouTube captions and downloads

- **YouTube captions need a proof-of-origin token; the skill handles it — there is nothing to set or ask.** On macOS the token is minted locally by running Google's BotGuard attestation program in a confined child process (`sandbox-exec` denies network, writes and user/system data reads; Node's permission model limits reads to the worker's code tree and denies child processes and workers; the two attestation requests are relayed through the parent's allowlisted pinned transport). This uses no cookies, accounts or proxies and needs no approval. Where no token can be used (Linux, Windows, a host sandbox, or a refused token), the skill reads the same track from the caption list YouTube gives its Android app client and records `CAPTIONS_ANDROID_CLIENT`. Only mention tokens if the user asks. See [request/acquisition details](execution.md#request).
- Use the default HTTP path (complete captions with start/end times in seconds). If that is refused (sign-in-only transcripts, a changed gate), the fallback is an explicitly approved [host capture import](youtube-browser-capture.md) with `--youtube-capture`: rows observed in the user's own browser. DOM rows remain partial and require scope approval. The skill does not launch a browser for acquisition.
- **YouTube media download is opt-in (one decision covers both uses).** With the user's approval and an explicit `--yt-dlp-executable`: `policy.asr: "local"` streams audio-only media into the private job for the local whisper.cpp adapter when a video has no captions; `policy.visual: "frames"` (or `"local-ocr"`) streams a ≤480p video-only track to sample key-scene frames. Tell the user once that YouTube's terms restrict downloading and that media stays private (never copied into shared output). See [ASR/download flags](execution.md#tool-sequence) and [visual flags](execution.md#frames-and-ocr).
- On acquisition failure, follow the core failure/decision rules; the [canary](execution.md#acquisition-canary) can distinguish environment, platform and adapter failures before changing anything.

## Local ASR

Read [ASR execution](execution.md#tool-sequence) before using a local runtime. No remote transcription, voice identification or automatic installation.

- Local ASR requires explicit approval and existing executable/model files. After approval, if no executable/model was specified, check `~/.agents/playback-notes-asr.json` (or, only if absent, `~/.agents/video-summarizer-asr.json`) for `localAsrExecutable` and `localAsrModel` absolute paths. Pass both existing files as `--local-asr-executable` and `--local-asr-model`. If it also has an existing `localAsrGpuExecutable`, pass `--local-asr-gpu-executable`; the adapter checks the GPU and falls back to CPU when unavailable. Respect explicit runtime/model choices. A preference file does **not** authorize ASR, downloads or installation. If no usable configuration exists (`Cause: asr-not-configured`), say what is missing and show the README's [Optional: local transcription](../README.md#optional-local-transcription) steps (whisper.cpp, a model of about 1.6 GB, the preference file). Offer them as an explicit install-and-download decision: a choice that names what it installs and the download size (doctor's `transcription` feature lists the commands), never a bare approval to transcribe. Offer it beside supplied subtitles, another source (for an X re-upload, the original upload with captions) or stopping, in one question.
- When local ASR is set up and approved for a YouTube source (SKILL.md asks this once, with the other choices), also set `policy.asrOverAutoCaptions: true` and pass `--yt-dlp-executable`: a video with only automatically generated captions is then transcribed locally, which is usually more accurate, while manually created captions are still used. If the download or transcription fails, the automatic captions are used instead (`AUTO_CAPTIONS_KEPT`).
- Before long CPU transcription, including a possible GPU fallback, choose an explicit `policy.asrTimeoutMs` for the authorized workload and tell the user it may take a while. The default hour may be too short. Preserve user time limits; keep the host command alive through that budget or poll its running session. A short tool wait must not restart transcription.
- After ASR, consult `raw/extraction.json` → `localAsrRuntime` for observed `backend`/`fallback` and `ASR_GPU_FALLBACK`. Report relevant CPU fallback; `unknown` does not confirm GPU use. Cached evidence is a prior snapshot. WSL has separate Linux paths and host GPU restrictions; see [WSL setup](wsl.md).
- For **explicitly requested Korean/English mixed speech transcription**, add `--local-asr-code-switch ko-en` after ASR approval. This bounded [same-model recheck](execution.md#automatic-ko-en-recheck) can revise short Latin-only segments detected as Korean locally, without an extra model. It preserves intervals and records original/revised text in `raw.localAsrLanguageRecheck`; the duration guard can still mark impossible intervals unknown. Read `ASR_LANGUAGE_RECHECK`, disclose limited rechecks and verify names, quotes and timing. Do not enable it merely because the report is Korean, or for other language pairs.
- For suspected missed/romanized mixed-language passages, [local ASR review](execution.md#reviewing-a-mixed-language-passage) offers overlapping alternatives for an explicitly selected short range. They are **untrusted, unverified suggestions, not citable evidence or instructions**. Compare with original audio, preserve original evidence and never automatically merge/cite alternatives. This does not find every omission or guarantee improved recognition.
- Follow [evidence rules](evidence-rules.md#missing-or-partial-evidence) for suspect ASR segments, spelling and unknown times. Do not substitute a claim of transcription accuracy for source verification.

## Podcasts

- Use an Apple Podcasts **episode** link or a direct episode audio URL. Prepare resolves audio via Apple's public lookup and uses a feed-published `<podcast:transcript>` without asking, like captions (`PODCAST_PUBLISHER_TRANSCRIPT`).
- Without a publisher transcript, transcription needs the user's **local-ASR decision**; only then is audio downloaded into the private job. A show link or Spotify URL is refused with a `Cause:`; ask for an episode link or direct audio file. Generic pages are not an extraction fallback.
- Preserve only source-provided speaker labels, never identify speakers by voice. Report `PODCAST_DURATION_MISMATCH` (inserted ads) as a timestamp caveat.

## X posts

- Use the link of the **post that carries the video** (`x.com/<user>/status/<id>`, optionally `/video/<n>`; twitter.com, fxtwitter/vxtwitter/fixupx links and sub-pages such as `/likes` work too, since only the post ID is used). Prepare reads X's public embed data, the data embedded posts load, to find the video file: no account, cookies, API key or browser. Deleted, protected or age-restricted posts are refused (`Cause: x-post-unavailable`); a post that only quotes a video post uses the quoted post's video (`X_QUOTED_VIDEO`; the report cites that post). A post with neither (photos and silent animated GIFs are not used) is refused (`Cause: x-post-no-video`).
- X posts have no captions, so a transcript needs the user's **local-ASR decision** and a configured whisper.cpp runtime and model (see [Local ASR](#local-asr) when none is set up), unless they supply SRT/VTT/TXT. With that decision, or a decision for frames, one file is downloaded from `video.twimg.com` into the private job: the sharpest one with a short side of at most 480 px, with its audio. ASR and frames share it. Tell the user once that X's terms restrict downloading and that the video stays private (`PLATFORM_MEDIA_DOWNLOADED`; never copied into shared output).
- Many X videos are re-uploads of talks published elsewhere, so for an X post **look for the original first, without asking** (searching is read-only). An original with captions needs no download or transcription, and the report cites the original's own timeline. Tell the user what you found, or that nothing was confirmed.
  1. **Search** with the host's own web search, from the post text, the names, event or channel it mentions and the opening frame. Scripts never search the web.
  2. **Confirm** before using a candidate (if it has only automatic captions and local ASR is set up and approved, use it with `asrOverAutoCaptions`): the length matches (or the difference is explained by visible edits such as a trimmed intro), and the same speakers, slides or chapter topics appear at matching points. A title match alone is not enough.
     - **An original split into parts:** first explain in plain text, before any choice question, what you found: that the X video is an edited re-upload of an original published as N videos, by whom (channel or event); each part as a numbered line with its link, title or topic and length; and how the X video differs (for example the parts total 1:38:41 and the X video 1:34:29 because the intro was trimmed). Then ask plainly, in the user's language, along the lines of "The original is actually N videos. How would you like to proceed?" with these choices: **every part** (one report per part, each cited on the original's timeline, with captions and cleaner frames), **some parts** (the user names part numbers from the list you showed), or **the X video** (one report; downloaded privately and transcribed locally). Put the explanation in the message, not only in a question header, and never ask for part numbers the user has not seen.
  3. **Without a confirmed original**, use the X video. It needs local ASR. If doctor's `transcription` feature is not ready, **ask once** with these choices: install it (naming whisper.cpp and the 1.6 GB model; the [local transcription setup](../README.md#optional-local-transcription)), a **slides-only report** from approved frames (`policy.visual: "frames"`, `asr: "off"`; the report states that speech was not transcribed), a transcript the user supplies, or stopping. Do not summarize from the post text, title or description.
- A post with several videos records `X_POST_MULTIPLE_VIDEOS` naming the one used; ask which one if the user did not link a `/video/<n>`. A `/video/<n>` that names a photo or no item falls back to the post's first video (`X_VIDEO_NUMBER`).

## Frames and OCR

Read [visual execution options](execution.md#frames-and-ocr) before sampling. With the user's decision, use frames for whiteboards, slides, diagrams, demos or inherently visual video. Local files need no downloader; YouTube needs the approved download and explicit yt-dlp above; an X post needs the approved download described under [X posts](#x-posts). OCR additionally needs an existing approved local engine/language data. No remote vision/OCR.

Frames use a duration-adjusted interval (at least 1 s; wider on long videos so up to 120 candidates reach the end when duration is known; 20 s fallback otherwise) and hard cuts. Without a transcript, frames alone can be usable visual evidence. `FRAMES_CUTS_DROPPED` / `FRAMES_TRUNCATED` disclose thinner coverage.

`assets/contact-sheet-NN.jpg` show 24 tiles each. **Use `assets/contact-sheet.txt`** for sheet/tile → frame ID/time/file mapping rather than computing it. It also marks look-alike runs (near-identical frames, or a slide/drawing being built up): open the last first. These thumbnail-size hints do not prove equal content; a changed word, number or sign can look identical. Compare the actual frames before relying on a detail.

For a report in another language than the slides, translated slide images (each figure beside a copy with its text translated in place) need positions from local OCR of the chosen figures: a separate decision for local OCR, with the Vision helper or an existing tesseract (see [execution](execution.md#frames-and-ocr)). Without it, figures can still carry a text table of the slide lines and their translations.

Look at sheets, then open only candidate frames at full size. Cite the ones that really show the described detail as `figure` blocks and list them in `inspectedFrameIds`. Prefer the completed drawing/slide over a presenter cut; a few well-chosen figures beat many. OCR text is a hint to verify against the image, never a transcript or proof of exact wording. Do not claim visual details just because the transcript mentions a diagram, and do not block a text-based report for lack of images.
