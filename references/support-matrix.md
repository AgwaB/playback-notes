# v1 support and verification boundaries

“Implemented” and “live verified” are deliberately separate. This repository is a reusable host-agent skill, not a standalone summarization service.

| Capability | v1 behavior | Verification / limit |
|---|---|---|
| Briefing / deep-dive | Same grounded report schema; host chooses depth | Schema/render paths tested; editorial quality remains the host's responsibility |
| Local MP4 / audio + supplied SRT/VTT/TXT | Acquires transcript, probes media, preserves source access | Real generated MP4/WAV, worker, ffprobe and subtitle parser tested |
| Captioned YouTube | One watch-page read and one caption-track read; with `youtubeTokens: botguard` the request carries a locally minted proof-of-origin token | Live, token on: 6/6 captioned test videos (TED 20 min, MIT 43 min, Karpathy 1 h, Lex 3.5 h, Python 2 min, EBS 5 min) returned complete json3 with start/end times in 3–4 s each; token off: 0-byte bodies (`Cause: transcript-refused`). Minting ≈0.8 s, ≈110 KB |
| BotGuard token minting | Opt-in, macOS only; bgutils-js + jsdom execute Google's downloaded attestation program in a confined child: `sandbox-exec` (deny network*; file contents under `/Users`, temp, `/private/var/{db,log,root,tmp}`, `/private/etc`, keychains, application support/preferences and volumes unreadable, re-allowed only for the Node install and the allowed code — a deny list: a symlink in `node_modules` to a readable system file elsewhere is not blocked at the OS layer) → `node --permission` (Node-level reads limited to the worker, `node_modules`, `package.json`; no child processes/workers/addons/WASI) with a 256 MiB old-space cap (not a total-memory bound) and a 90 s kill. The child talks newline-JSON over plain stdin/stdout (never Node's privileged IPC): records framed on raw bytes, 2 MiB/record and 8 MiB aggregate counted in bytes before decoding, strict UTF-8, every field type-checked before use, duplicate ids and trailing residue refused; eighteen malformed-child cases become clean rejections (the probe set, not a proof for every possible message). Its requests are relayed only to `https://www.youtube.com/api/jnn/v1/{Create,GenerateIT}`, POST, five allowlisted headers (the parent owns Host/Content-Length/connection framing), string bodies ≤1 MiB, ≤8 requests, on a 16 MiB pinned transport cancelled when the mint ends; a result while a relay is pending is refused | Live: TED 427 segments in 2.8–7 s under confinement. Tests: real sandboxed probe (write/read/spawn/worker denied, loopback and internet fetch blocked, symlink out of the allowed tree `EPERM`, PID identity), relay validation (21 rejection cases), ten hostile-child protocol cases plus a cooperative-child positive control, offline worker refusal through the relay. Not available on Linux/Windows (policy refused). The confined program can still read its own code and `process.report` host metadata; the token it returns is sent to YouTube by design |
| Host-browser YouTube capture | Explicit `--youtube-capture` imports a bound json3 response or observed DOM rows; no automatic browser/fallback | Real short-video DOM → production evidence verified (3 rows, partial, unknown ends). json3 path fixture-tested only; the long TED video was captured and reported through this path in v9 (see progress log). Since the token path acquires complete captions, this is the fallback for sign-in-only transcripts. See [capture contract](youtube-browser-capture.md) |
| Managed-browser YouTube | **Removed** (v14): with proof-of-origin tokens the HTTP path acquires 6/6 captioned test videos, while the anonymous Chrome path acquired 2/8 and carried the largest risk surface (browser launch, keychain prompt, request relay). Host-capture import remains the fallback | Before removal: real short-video acquisition yielded 3 partial DOM rows with 467 blocked requests; live json3 stayed empty and long TED was denied to anonymous sessions (HTTP 400) |
| Captionless YouTube, ASR off | Explicit transcript/capability decision | No remote ASR/LLM fallback |
| YouTube local-ASR fallback | Opt-in: `asr: local` + explicit `--yt-dlp-executable` downloads audio-only media (size-capped, no playlist/cache/remote components, Node as JS runtime) and feeds the existing whisper.cpp adapter; captions always win when present | Live: Big Buck Bunny (10:34, no captions) → yt-dlp 2026.10.21 audio in 3 s → whisper small (v2 build) → 67 non-speech segments in 31 s total. An outdated yt-dlp (2026.06) failed with HTTP 403: keep it current. Fake-binary argument contract tested |
| Direct media URL | Public HTTP(S), DNS-pinned/redirect-checked transport; supplied transcript or approved local ASR | Real guarded WAV download→probe→local ASR→HTML/Markdown/PDF verified for one 11-second English sample; native remote seek also verified |
| Other platform URL | User transcript may be supplied; no automatic platform extractor | Not general website summarization |
| Local ASR | Explicit existing whisper.cpp executable/model; POSIX only | Approved whisper.cpp 1.9.5 + tiny passed local/direct English WAV exports. Expanded Korean/noisy/long tests found quantity/condition corruption, omissions and three small tail-overrun rejections. Evidence acquisition success is not faithful recognition; see audio acceptance |
| Experimental ASR v2 + small | Private decoder fork usable as the explicit local executable; unmodified upstream still rejects overruns | 24/24 timestamp-bound cases pass; through production `prepare.mjs`, the three formerly rejected fixtures now pass with tiny and small while unmodified 1.9.5 still fails. Small improves Korean CER, but sensitive conditions/numbers remain corrupted or omitted. Parent reverified artifacts, model hash and metrics; see [v9 ASR report](../docs/asr-resolution-v9.md) |
| YouTube audio for ASR (yt-dlp) | `--ignore-config --no-plugin-dirs` (installed configuration/plugins cannot add cookies, proxies or hooks), `-f bestaudio` with no video fallback, canonical watch URL only, `-f "bestaudio[protocol=https]" -o -`: only plain-HTTPS audio formats (fragmented DASH/HLS would be staged as fragment files by yt-dlp regardless of `-o -`), streamed and saved by the skill through its metered pipe, so `maxDownloadBytes` is enforced as bytes arrive (tool killed, partial file removed); no output template; a non-zero tool exit is `download-failed`; the result must probe as audio-only | Live: Big Buck Bunny (10:34, no captions) → 10 MB opus streamed in 4 s → probe audio → whisper small 67 segments, 30 s total. | Local ASR model: large-v3-turbo | Recommended model for Korean / instruction-bearing speech; official `ggerganov/whisper.cpp` pinned revision, SHA-256 verified before use; `ASR_MODEL_COMPACT` flags sub-GiB models | Same seven frozen Korean fixtures, same v2 runtime and flags: clean CER 0.4–2.9 % (small 1.2–4.8 %), noisy 2.4–7.1 % (small 4.8–28.6 %; the reduction is 4.0× on natural-noise, 2.9× procedure-noise, 2.0× explanation-noise); of 19 *selected* sensitive assertions 11 retained / 8 partial / 0 omitted (small 8 / 10 / 1) — not all sentences, and the long fixture still renders “새 사본” as “3,4번” outside the selected set; every quote is in `sensitive-review-turbo.json`. Residual partials: 검증→검진 and 밑→및 under noise; “예시→예술” reproduces on freshly synthesised TTS of the same text (a fixture/TTS effect that turbo does not overcome), “이 도” becomes correct only when the script reads “2도”. Run time 1.1–6.5× small (0.3–0.9× real time on this Mac); beam search 5 changed nothing on the three re-run fixtures. Production `prepare.mjs` with turbo: 12 segments to 64.7 s of 66.8 s, no timing issues. Not a listening-based certification |
| Remote ASR / summarization API | Excluded | Ambient provider keys/config are not inherited by the worker |
| Local OCR frames | `policy.visual: local-ocr` with an explicit tesseract executable; ffmpeg selects source frames at scene changes or at a fixed interval (`select`, keeping each frame's real presentation timestamp; frames stream to the skill as one mjpeg pipe and are split and written here, so the 64 MiB budget is enforced while sampling; `passthrough` + `setpts` after the metadata print guarantee one image per timestamp record even for duplicate-PTS sources; ≤600 frames; fitted within 1280×720), OCR text is deduplicated exactly (identical after NFC + whitespace collapsing within 10 s of sampled source time; never by similarity or punctuation normalisation), frames carry `ocrText`; visual-only evidence allowed when no transcript exists; local media only | Text cards: real tesseract 5.5 (`kor+eng`, psm 6) read 4/4 Korean cards; a fresh host confirmed each frame and exported HTML/MD/PDF. Real footage (KBS news clip, 77 s, burned-in lower-thirds): tesseract produced garbage in every mode, the Apple Vision helper (`scripts/vision-ocr.swift`, `--ocr-engine vision`) read both headline captions correctly (the ticker and poster text in the same frames is partly garbled); `--ocr-region bottom` cut kept frames 20→7 and the dedupe suppressed the repeated logo. Measured on this one clip and the synthetic cards only — dense slides and non-Korean subtitles are not characterised. Vision is macOS-only; no OCR for platform media |
| Caption track priority | `policy.transcriptLanguages` (youtube-transcript-api order: language priority, then manual over auto-generated) applied to HTTP tracks; captures may declare `trackKind` | Ranking unit-tested; live: `["en","ko"]` picked `en` on TED/MIT and `ko` on EBS |
| Failure causes | Fixed `Cause:` vocabulary (bot check, age restriction, unavailable, unplayable, no transcript, refused, empty) mirrored from youtube-transcript-api | Playability mapping unit-tested; live bot-check and no-transcript cases observed in the topic matrix |
| HTML | Fixed responsive document, transcript/source panel, pin/follow controls | Desktop/mobile, escaping, offline document reading and native seek tested in local Chrome |
| YouTube player | Official IFrame API; transcript/source-link fallback | Blocked-player fallback tested; actual official embed decoded near requested 4 s for one live video. Not a general availability guarantee |
| Diagrams | Structured `stack`/`flow` blocks rendered to inline SVG by the fixed renderer; Markdown gets the same content as a list | Escaping, orthogonal-connector, focal-budget, cycle/reference rejection and determinism tested; two real diagrams verified in a Korean PDF. ## Important interpretations

- Extraction `complete` means the selected transcript response/file was acquired. It does not prove every spoken word or visual was captured, nor that supplied text corresponds to the media.
- Script validation proves structure/bindings, not factual correctness or actual human/model attention.
- An HTML file opened directly remains a readable report. Embedded playback may need the local HTTP server; external sources may reject embedding.
- Shared local-source reports normally omit source media. Keep the whole output folder for images; explicitly opt in before copying media.
- UI labels are Korean for Korean output and English otherwise. Arbitrary report-language text is accepted, but fonts/language fidelity beyond tested cases must be checked.
